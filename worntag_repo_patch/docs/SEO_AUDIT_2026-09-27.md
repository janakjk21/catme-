# WornTag SEO audit and improvement log

**Reviewed:** 27 September 2026  
**Canonical domain:** `https://worntag.com/`  
**Audit basis:** live HTTP responses and source review for the eight indexable site pages; no Search Console, analytics, paid keyword, backlink or PageSpeed account data was available in this pass.

## Method

Used the checklist and prioritisation approach from [AgriciDaniel/claude-seo](https://github.com/AgriciDaniel/claude-seo/tree/e77e783e38eeb738424eb72117abbd2dacdd88af), version 2.4.0 at the reviewed commit. Relevant material: `seo-audit`, `seo-technical`, `seo-content`, `seo-images`, `seo-schema`, `seo-sitemap`, `seo-geo`, and `seo-agentic`.

The repository is a Claude Code plugin, so its managed runtime and optional services were not installed or run here. The checks below were applied directly to WornTag. No paid SEO APIs or user credentials were used. Its advice was checked against current Google Search Central documentation where applicable; repository claims are treated as recommendations, not ranking guarantees.

## Findings and changes

| Priority | Finding | Change / evidence |
|---|---|---|
| High | Before the fix, apex and `www` both returned the same homepage with HTTP 200, while page canonicals and the sitemap preferred the apex. | Added and production-verified a single-hop permanent redirect from `www.worntag.com` to `worntag.com`, preserving path and query. `/index.html` redirects to `/`; combined www + `/index.html` also reaches the final URL in one hop. Google treats redirects as a stronger canonical signal than sitemap inclusion. |
| High | Homepage had Organization JSON-LD, but no `WebSite` node expressing the preferred site name. | Added a truthful `WebSite` node for “WornTag” with `worntag.com` as its alternate name, linked to the existing Organization node. JSON-LD parses successfully. Google recommends this markup to indicate a preferred site name; it does not guarantee what Google displays. |
| Medium | The beta status endpoint was crawlable under the broad `Allow: /` rule. | Added `Disallow: /api/` while keeping public pages and assets crawlable. This controls crawling only; it is not access control. |
| Medium | Open Graph image alt was missing on the Privacy and Terms pages; social image descriptions were inconsistent across pages. | Added consistent `og:site_name`, `og:image:alt`, and `twitter:image:alt` metadata across the eight public pages. All inline page images already had descriptive, non-empty `alt` attributes. |
| Pass | Crawl and indexation basics. | `robots.txt` and `sitemap.xml` return 200. Sitemap contains eight HTTPS canonical pages. All eight canonical apex page URLs returned 200 after deployment; all sampled `www` URLs returned a single 301 to apex. Each page has a unique title, meta description, and canonical. A sitemap is a discovery hint, not proof of indexing. The sitemap omits `<lastmod>` rather than asserting unverified dates. |
| Pass | Image delivery and layout stability. | Site imagery uses WebP; largest asset reviewed is about 148 KB. Inline `<img>` elements have descriptive alt text and width/height. Homepage hero is eager/preloaded with high fetch priority; below-fold cards are lazy loaded. |
| Note | FAQ structured data. | FAQPage JSON-LD parses and matches the visible FAQ. Google stopped displaying FAQ rich results on 7 May 2026, so this markup is not counted as a Google rich-result opportunity. Markup was syntax-checked locally; no external schema validator or Rich Results Test receipt is claimed. |
| Note | AI/agent discovery files. | No `llms.txt` is present. The reviewed SEO repository assigns it no Google visibility value, and Google says such files are not required for Search and do not affect ranking. It was not added as an SEO tactic. Current HTML is server-delivered and the robots file allows public content to be fetched. |

## Content and trust review

- **Strengths:** the “Closer than a photo” positioning is consistent; concept artwork is labeled as concept imagery; app availability, upload, pricing and memory boundaries are stated honestly; editorial stories are not presented as customer testimonials.
- **Main content opportunity:** replace some repeated pre-launch caveats with one concrete, accurate first-use moment and clearer beta learning goals. Do not invent features or publish keyword-swapped pages without evidence of distinct user value.
- **Trust information still missing:** founder/company identity, public support/privacy contact, and genuine tester evidence. Add these only after the owner supplies verified details; do not invent author credentials, contact details, or testimonials.
- **Beta:** page and database endpoint are deployed, but no Railway PostgreSQL service or `DATABASE_URL` exists. The public signup remains closed and test submission returns HTTP 503. Do not describe collection as active.

## Remaining verification

1. Crawl all internal HTML links on the deployed canonical host; 142 local internal links resolved, but that is not a full live crawl.

5. Only add tracking, AI crawler restrictions, or an `llms.txt` file after an explicit product/privacy decision and evidence of a useful purpose.

## Follow-up verification (27 September 2026, 20:09 UTC)

This follow-up checked the production site after the interrupted deployment turn:

- All eight sitemap pages returned HTTP 200 on `https://worntag.com`.
- `/robots.txt`, `/sitemap.xml`, and `/health` returned HTTP 200; the robots file disallows `/api/` and points to the canonical sitemap.
- `https://www.worntag.com/index.html?ref=seo` returned one HTTP 301 to `https://worntag.com/?ref=seo`, preserving the query string.
- `/api/beta-signups/status` returned `{"open":false}`. No signup was submitted and no subscriber data was accessed.
- The deployed homepage response includes the expected security headers. This is an observation only, not a security assessment.

The website SEO implementation is deployed and the HTTP-level items above are live-verified. Search Console/Bing indexing and selected-canonical state, a full live internal-link crawl, PageSpeed/CWV, and accessibility review are still outstanding. The patch and docs remain in the CatMe checkout's untracked `worntag_repo_patch/` folder; this is not the WornTag website Git repository, and no commit or GitHub push was made.
