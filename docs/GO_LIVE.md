# Production go-live checklist

Owner-run only. Payments, Sign in with Apple and App Store submission wait for the paid Apple Developer account. Do not turn on live generation until the phone flow, photo checks, consent and provider budget are verified.

1. **Freeze and verify the branches.** Run API `npm test`; run Unity EditMode tests, rebuild the place with the last seed, play the full app, and make a signed iPhone build. Record the API and app commit hashes. Merge `catme-ai` branch `claude/focused-faraday-eemw65` to `main` first, verify Railway deploys that API commit and `/health` responds. Merge the app branch only after the API accepts its request and response shapes.
2. **Set Railway production variables.** Set `GENERATION_MODE=live`, `PHOTO_CHECK_REQUIRED=1`, `OPENAI_API_KEY`, Tripo and Meshy credentials already named in the API README, `CATME_FREE_PETS` and `CATME_FREE_OWNERS` to the approved per-account allowances, `CATME_GUEST_FREE_PETS=1`, and conservative `CATME_DAILY_PET_CAP` / `CATME_DAILY_OWNER_CAP` after deciding the daily spend budget. Set `GENERATION_DOGS=1` only after one dog model has been verified and dog spend approved. Set `CATME_REVIEW_UIDS` to only the dedicated review account UID(s); remove them after review. Keep `CATME_REQUIRE_APP_CHECK` unset/false until the app and Firebase App Check are configured and tested; then set it to `true` in a separate rollout.
3. **Publish security rules after review.** From the Firebase-configured repo, inspect the target project with `firebase use` and review `firestore.rules` and `storage.rules`. Then run `firebase deploy --only firestore:rules,storage` against the intended project. Test one guest and one signed-in account: own reads/writes work; cross-account reads/writes fail.
4. **Smoke-test without uncontrolled spend.** Check `GET /health` over HTTPS. With a dedicated test account, verify session, consent and uploads, then approve a single live cat and person generation. Confirm a wrong-animal or unsafe photo is rejected before providers, failed jobs do not consume quota, a ready model downloads on a second device, and deletion removes server data. Watch Railway logs and Firestore `generationUsage/{UTC-date}` during the test. Never put provider keys or review credentials in Git.
5. **Check network reachability.** From an IPv6-capable network, resolve both A and AAAA records for the API host and run `curl -6 -I https://<api-host>/health` when an AAAA route exists. Also test cellular and Wi-Fi on the iPhone; an HTTP 200 from one desktop route is not device reachability.
6. **Review monitoring and rollback.** Keep Railway logs open during review; watch 5xx, `CHECK_UNAVAILABLE`, provider failures, daily-cap refusals, latency and spend. Roll back the API deployment if creation or deletion regresses. Keep the prior signed app build available until a new build passes full Play Mode and phone checks.

Record the final URL, commit hashes, variable values (not secrets), rules deploy target/time, smoke-test receipts, iPhone build number, App Review account UID and unresolved issues in `context/STATUS.md` before submission.
