# Durable Decisions

Record only choices that future work must preserve. Newest entries go first.

## 2026-09-21 — Shop and inventory live through room objects

A physical room catalog opens the shop. Studio Cat previews show signature actions. Tokens come from play, memories, discoveries, and bond milestones. Cats have food preferences, while unlocked toys and decorations can be placed in valid room locations.

## 2026-09-21 — Feeding uses an authored occluded station

The player places visible food at a wall-facing bowl. The cat walks to an authored point, while room geometry, camera framing, sound, and subtle procedural motion imply eating without requiring an eating clip.

## 2026-09-21 — Studio Cats use direct purchases and items use earned tokens

Studio Cats are clear one-time purchases. A soft token may unlock food varieties, toys, and room items, while basic care remains available and bond cannot be purchased.

## 2026-09-21 — Variable greeting, named cats, and hybrid memories

Every cat receives a player-selected name. On return it may greet the player or continue its activity. Memories combine player photographs with occasional candid captures.

## 2026-09-21 — Ambient realistic companion design

The product supports personalized, memorial, and virtual cats through one realistic experience. It uses a guided room camera, autonomous behavior, physical props, real-world lighting, and direct petting instead of constant character control.

## 2026-09-21 — Gentle needs and permanent bond

Energy, mood, and hunger change behavior without punishment. Bond grows through varied care, never decreases, and unlocks reactions and memories. The interface shows a heart meter plus relationship stages.

## 2026-09-21 — One active cat and memory-led return loop

Players may own personalized and purchasable Studio Cats but keep one active in the initial room. Candid memories and discoveries encourage returning without relying on a daily task checklist.

## 2026-09-21 — Architecture and security are routed context

Architecture and security requirements live in dedicated modules. Agents load them only for cross-system changes or work involving networking, user data, permissions, storage, purchases, or release.

## 2026-09-21 — Context is modular

Agents read `STATUS.md` plus the single topic module relevant to their task. The detailed implementation reference is reserved for cross-system design and unresolved requirements.

## 2026-09-21 — Editor first, iOS first

Build the core prototype in the Unity Editor, validate it on iOS first, and add Android device work after the interaction loop is convincing. Gameplay code remains cross-platform.

## 2026-09-21 — Local cat before network integration

Prove loading, materials, animation, axes, scale, locomotion, and room behavior using the local walking GLB. Do not spend provider credits or connect remote generation during these milestones.

## 2026-09-21 — Server owns generation

Meshy and Tripo credentials, polling, errors, validation, and optimization remain on the server. Unity consumes a versioned manifest and an optimized GLB.
